1. Funcionalidad Principal Definida

Gestión de Carrito y Procesamiento de Pagos

La funcionalidad central elegida para esta práctica es el flujo de compra de una aplicación de entrega de comida. Abarca desde que el usuario agrega productos al carrito, la validación de horarios del restaurante, hasta el procesamiento final del pago (exitoso o denegado).

2. Escenarios de Prueba (Gherkin)

Escenario 1: Agregar producto (Caso Exitoso)

Objetivo: Valida que el sistema actualice el contador de artículos y calcule correctamente el subtotal cuando un usuario añade un producto por primera vez.

Feature: Gestión del carrito de compras

Scenario: Agregar un producto al carrito vacío
  Given que el usuario ha iniciado sesión en la aplicación
  And el carrito de compras está vacío
  When el usuario agrega "1 Pizza Familiar" al carrito
  Then el ícono del carrito debe mostrar "1" artículo
  And el subtotal a pagar debe ser "$18.00"

Escenario 2: Pago aprobado (Caso Exitoso)

Objetivo: Valida el flujo completo de checkout comprobando que una tarjeta con fondos apruebe el pedido y genere la confirmación.

Scenario: Procesar el pago de un pedido con tarjeta válida
  Given que el usuario tiene productos en el carrito por un total de "$25.00"
  And se encuentra en la pantalla de confirmación de pago
  When el usuario ingresa una tarjeta de crédito válida
  And presiona el botón "Pagar Ahora"
  Then el sistema debe procesar el cobro exitosamente
  And redirigir a la pantalla de "Pedido Confirmado"
  And enviar un recibo al correo del usuario

Escenario 3: Tarjeta rechazada (Caso de Error)

Objetivo: Valida que la aplicación maneje correctamente las denegaciones bancarias, mostrando un error amigable sin perder los artículos del carrito.

Scenario: Intento de pago con tarjeta sin fondos suficientes
  Given que el usuario intenta pagar un total de "$30.00"
  When el usuario ingresa una tarjeta de crédito sin fondos
  And presiona el botón "Pagar Ahora"
  Then el sistema bancario debe rechazar la transacción
  And el sistema debe mostrar la alerta "Pago declinado. Verifique su balance."
  And el carrito de compras debe conservar los productos seleccionados

Escenario 4: Restaurante cerrado (Caso de Error)

Objetivo: Valida la lógica de negocio respecto a los horarios de atención, evitando que se envíen pedidos a comercios que ya no están operando.

Scenario: Realizar un pedido fuera del horario de servicio
  Given que el usuario está viendo el menú de "Pizzería Rafa"
  And el horario actual es "11:30 PM"
  And el horario de cierre del establecimiento es "10:00 PM"
  When el usuario intenta agregar un producto al carrito
  Then el sistema debe bloquear la acción
  And mostrar el mensaje "Restaurante cerrado. Abre mañana a las 11:00 AM"

Escenario 5: Uso de cupón promocional (Caso Exitoso)

Objetivo: Valida el motor de promociones, comprobando que se apliquen las deducciones matemáticas correctas al total antes de pagar.

Scenario: Aplicar un cupón de descuento válido antes del pago
  Given que el usuario tiene un pedido con un subtotal de "$20.00"
  When el usuario ingresa el cupón "DESC20" en la caja de texto
  And presiona el botón "Aplicar"
  Then el sistema debe validar el cupón como exitoso
  And el nuevo total a pagar debe actualizarse a "$16.00"
  And mostrar un mensaje en verde indicando "-20% aplicado"
